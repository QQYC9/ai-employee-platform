## 1. بنية الواجهة الجديدة وقرار التصميم المعماري

### القرار: تطبيق منفصل مستقل داخل `apps/tenant-dashboard` (Option 1)

تم فحص بنية المستودع بدقة ومقارنة الخيارين:
1. **الخيار الأول (المعتمد):** إنشاء تطبيق مستقل كلياً داخل `apps/tenant-dashboard` يعمل على منفذ/نطاق مستقل (`app.domain.com` للعملاء مقابل `admin.domain.com` للإدارة العليا).
2. **الخيار الثاني (المرفوض):** دمج واجهة العميل داخل مسار `/tenant/*` في `apps/admin-dashboard`.

### أسباب ومبررات اختيار البنية المنفصلة:
1. **الأمان الصارم وحظر تسريب الشيفرة (Zero Code Leakage):**
   - لوحة الإدارة العليا تحتوي على مسارات ومكونات شديدة الحساسية لإدارة المنصة (`/api/v1/admin/platform/*`, `/tenants/provision`, استعراض سجلات التدقيق لجميع الشركات).
   - إذا تم دمج الواجهتين في تطبيق واحد، فستتضمن حزمة الجافاسكريبت المترجمة المرسلة لمتصفح العميل هياكل البيانات ومسارات واستعلامات الإدارة العليا، مما يعرض أمان المنصة للخطر حتى لو تم إخفاء الأزرار.
2. **عزل جلسات المصادقة (Session Separation):**
   - العميل يستخدم مفاتيح تخزين مستقلة (`ai_employee_tenant_token` و `ai_employee_tenant_user`) لمنع أي تداخل بين جلسة مسؤول المنصة وجلسة العميل التجاري.
3. **خفة الحزمة وسرعة التحميل (Performance & Bundle Size):**
   - حزمة تطبيق العميل تبلغ **78.5 kB** فقط بعد الضغط (gzip)، وتخلو من مكتبات ومخططات الإدارة المعقدة، مما يمنح تجربة تصفح فورية وسلسة على الهاتف والحاسوب.
4. **مشاركة الاعتماديات بصفر استهلاك للمساحة (NTFS Directory Junction):**
   - تم ربط مجلد `node_modules` بمجلد الحزم المشترك دون تنزيل أو تكرار مكتبات إضافية، مما حافظ على سرعة البناء وثبات البيئة.

## 2. الصفحات والوظائف المنفذة وتجربة المستخدم

تم بناء واجهة احترافية كاملة باللغة العربية مع دعم RTL وتصميم SaaS حديث بطابع الذكاء الاصطناعي، متناسقة في الهوية ومتميزة بلون الزمردي والتيل (`emerald / teal`) المخصص لبيئة الأعمال:

### 1. صفحة تسجيل الدخول (`/login`)
- واجهة دخول متقدمة لعملاء المنصة تدعم البريد وكلمة المرور.
- فحص دور المستخدم وصلاحياته قبل نقله للوحة؛ ترفض أي حساب ليس له `tenant_id` أو يحمل صفة مسؤول منصة فقط، مع توضيح رسالة الحظر بالعربية:
  > *"هذه البوابة مخصصة لعملاء ومستأجري المنصة فقط. يتطلب تسجيل الدخول حساباً مرتبطاً بشركة أو مستأجر."*

### 2. لوحة العمليات الرئيسية (`/`)
- بطاقة ترحيب ذكية تعرض اسم الشركة المسجلة وشارة العزل الأمني.
- أربع بطاقات مؤشرات أداء حية (KPI Cards):
  1. **الموظفون الرقميون:** إجمالي الوكلاء وعدد النشطين منهم.
  2. **إجمالي المهام:** عدد المهام المنفذة ونسبة النجاح الفعلية.
  3. **استهلاك الرموز (Tokens):** الاستهلاك الشهري مقابل الحد الأقصى مع شريط تقدم ذكي وشارة تنبيهية.
  4. **قنوات التواصل:** عدد القنوات الفعالة (واتساب، ويب هوك).
- **حالة صندوق الرسائل والعمليات (Outbox):** مراقبة العمليات الجارية، الرسائل المكتملة، والرسائل العالقة لضمان موثوقية التنفيذ.
- **سجل المهام الأخيرة:** جدول يعرض آخر المهام المسندة مع حالاتها وأولوياتها.
- **أزرار الوصول السريع:** نوافذ منبثقة تفاعلية لإسناد مهمة جديدة فورياً أو إضافة موظف رقمي.

### 3. صفحة الموظفين الرقميين والوكلاء (`/agents`)
- شبكة بطاقات تفاعلية لعرض فريق العمل الرقمي للشركة.
- عرض نوع الوكيل ومحرك التفكير (`ReAct Agent`, `Assistant`, `Specialist`).
- تصفية فورية بحسب الاسم والحالة (الكل، النشطة، المتوقفة).
- زر تفعيل/إيقاف مؤقت للوكيل مع تحديث فوري للحالة عبر الـ API.
- نافذة منبثقة لإنشاء وكيل ذكي جديد وتعيين تخصصه ومحركه.
- نافذة تعديل بيانات الوكيل.

### 4. صفحة سجل ومتابعة المهام (`/tasks`)
- جدول متكامل لمتابعة سير تنفيذ المهام ومخرجات الذكاء الاصطناعي.
- تصفية متقدمة بحسب الحالة (المكتملة، قيد التنفيذ، الفاشلة، قيد الانتظار) والتصفية بحسب الوكيل المسند إليه.
- عرض رسائل الخطأ التفصيلية في حال تعثر أي مهمة.
- نافذة تفاصيل المهمة (Modal) تعرض الهدف، الحالة، المخرجات بصيغة JSON، وسجل الأخطاء.
- **إعادة المحاولة (Retry):** زر مخصص لإعادة جدولة المهام المتعثرة مع تأكيد وإشعار نجاح فوري.
- **إلغاء المهمة (Cancel):** زر آمن لإلغاء المهام الجارية أو المعلقة.
- نافذة إسناد مهمة جديدة مع تحديد الأولوية (منخفضة، متوسطة، عالية، طارئة).

### 5. صفحة قنوات التواصل والرسائل (`/channels`)
- عرض القنوات المتصلة بالشركة (واتساب Meta Cloud API، واجهات Webhook).
- إشعار أمني بارز يؤكد تشفير وتأمين مفاتيح الربط والتوكنز السرية داخل مساحة المستأجر المعزولة وعدم كشفها في الواجهة.
- نافذة ربط قناة جديدة مع إدخال رقم الهاتف أو رابط الويب هوك.
- إمكانية قطع اتصال القناة مع نافذة تأكيد تحذيرية لحماية قنوات استقبال العملاء.

### 6. صفحة الاستخدام وحصة الرموز والميزانية (`/usage`)
- تفاصيل استهلاك رموز الذكاء الاصطناعي اليومية والشهرية مع أشرطة تقدم ونسب مئوية.
- مراقبة سقف الاستهلاك الصارم (Hard Limit) والتنبيه عند الاقتراب من الحد.
- جدول توزيع الاستهلاك بحسب مزود الذكاء الاصطناعي (Google Gemini, OpenAI).
- جدول توزيع الاستهلاك بحسب النموذج المستخدم (`gemini-1.5-pro`، إلخ).
- جدول الاتجاه اليومي للاستهلاك (Daily Trends) يوضح عدد الطلبات والرموز والأخطاء.
- إمكانية تصفية الفترة الزمنية (آخر 7 أيام، 30 يوماً، 90 يوماً).

### 7. صفحة إعدادات الشركة والعقل المؤسسي (`/settings`)
- بطاقة الملف الشخصي للمستخدم الحالي وصلاحياته داخل المستأجر.
- نموذج تحديث الاسم التجاري للشركة وحفظه مباشرة في الـ Backend.
- **العقل المؤسسي (BusinessBrain):**
  - نبرة وأسلوب التخاطب للوكلاء (Voice & Tone).
  - رسالة ورؤية الشركة لتوجيه ردود الوكلاء الرقميين.
  - سياسات وقواعد العمل الإلزامية التي يلتزم بها جميع الوكلاء في الرد والتنفيذ.
  - ملخص المنتجات والخدمات المعروضة.
  - حفظ وتحديث فوري لسياق الشركة في قاعدة البيانات.

## 4. نتائج اختبارات الصلاحيات وعزل المستأجرين (RBAC & Tenant Isolation)

تم إجراء اختبارات أمنية صارمة على الـ Backend والواجهة الأمامية للتحقق من استحالة اختراق حدود المستأجر:

```
========================================================================================
فحص الأمان وعزل المستأجرين                                              النتيجة الفعلية
========================================================================================
1. رفض دخول مسؤول المنصة العام بدون مستأجر لبوابة العميل                مرفوض (رسالة واضحة)
2. محاولة استعلام العميل عن لوحة مستأجر آخر (?tenant_id=foreign)         403 Forbidden
3. محاولة العميل استدعاء واجهات الإدارة العليا (/admin/platform/*)        403 Forbidden
4. محاولة العميل استدعاء إنشاء المستأجرين (/tenants/provision)           403 Forbidden
5. محاولة العميل استعلام مهمة تابعة لمستأجر آخر (/tasks/{foreign_id})    404 Not Found
6. حجب الأسرار والمفاتيح التشفيرية لقنوات التواصل                       مطهر بالكامل (Sanitized)
========================================================================================
```

> [!IMPORTANT]
> **تأكيد الأمان:** تم التحقق من أن جميع آليات الحماية والعزل مفروضة في **الـ Backend** وليس فقط في الـ Frontend، بحيث إن أي طلب برمجى مباشر (Direct HTTP Request) يحاول تجاوز نطاق المستأجر يتم رفضه فورياً برمز `403 Forbidden` أو `404 Not Found`.

## 7. الوظائف التي لم تنفذ وأسبابها المبررة

1. **إعادة شحن الرصيد والدفع المالي المباشر (Direct Payment Gateway):**
   - *السبب:* لم يتم في الـ Backend تفعيل تكامل بوابة دفع معتمدة (مثل Stripe أو Moyasar) حتى هذه المرحلة. تم الاكتفاء بعرض الاستهلاك، الحدود الفعلية، والتنبيهات، دون إضافة أزرار دفع وهمية.
2. **استخراج تقارير PDF للمهام من الواجهة:**
   - *السبب:* لا يوجد مسار Endpoint لتوليد ملفات PDF في الـ Backend حالياً. يمكن تنفيذها لاحقاً كـ Export API عند توفر المتطلب.
3. **حذف الوكيل نهائياً (Hard Delete Agent):**
   - *السبب:* لأسباب سلامة تدقيق العمليات (Audit Integrity) وعلاقات قواعد البيانات الخارجية مع المهام القديمة، يدعم الـ Backend التعطيل المؤقت (`inactive`) فقط، وتم الالتزام بذلك.
