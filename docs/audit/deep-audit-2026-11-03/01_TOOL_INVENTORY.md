## 1. مصفوفة الأدوات المتاحة وحدود صلاحياتها

| اسم الأداة (Tool Name) | الوظيفة الأساسية | متى تُستخدم في هذه المهمة؟ | ما الذي لا تستطيع فعله أو ممنوع فعله بها؟ |
| :--- | :--- | :--- | :--- |
| **`run_command`** | تشغيل أوامر Shell في الطرفية (PowerShell على Windows). | فحص Git، استكشاف الملفات والأدلة، تشغيل اختبارات معزولة، فحص تفرعات المستودعات الخارجية. | **ممنوع قطعيًا:** `git reset`, `git clean`, `git add -A`, تنفيذ ترحيلات على قاعدة الإنتاج، إعادة تشغيل Docker الحاويات، أو مسح ملفات. |
| **`read_file`** | قراءة الملفات النصية، الكود، الوثائق، وتحديد نطاق الأسطر. | القراءة المتعمقة لملفات المنصة (`services`, `models`, `engine`) وملفات المشاريع المرجعية الخارجية. | قراءة الملفات الثنائية (Binary) كنص، وتقتصر على 800 سطر / 46KB لكل استدعاء. |
| **`write_file`** | إنشاء ملفات جديدة أو استبدال ملفات بالكامل. | إنشاء وتحديث ملفات التدقيق الحي الـ 14 داخل `docs/audit/deep-audit-2026-11-03/`. | **ممنوع:** الكتابة فوق ملفات التطبيق العاملة أو حذف محتويات كود المشروع. |
| **`edit_file`** | إجراء تعديلات محددة على مقاطع نصية بدقة تامة. | تحديث السجلات والجداول عند الحاجة لإضافة اكتشاف دون إعادة كتابة الملف بالكامل. | **ممنوع:** تعديل كود المنصة في هذه المهمة لأنها Read-Only Audit. |
| **`search_web`** | البحث في الإنترنت ومحركات البحث. | التحقق من وثائق الإصدارات الرسمية، الـ Releases، والمستودعات للمشاريع المرجعية السبعة. | لا تغني عن فحص الكود المصدري الفعلي المنزّل محلياً. |
| **`invoke_subagent`** | إطلاق وكلاء فرعيين (Subagents) للعمل بالتوازي في الخلفية. | تفويض مهام فحص مستقلة (مثل دراسة موديول محدد في مستودع خارجي أو فحص مسارات الواجهات). | لا ينبغي إطلاق وكيل دون تحديد مدخلاته، مخرجاته المتوقعة، والدليل المطلوب. |
| **`define_subagent`** | تعريف أنواع مخصصة من الوكلاء وتحديد نظام عملهم. | إنشاء وكيل باحث متخصص (Codebase Researcher أو Benchmark Auditor). | الوكيل يرث حدود الأمان المعطاة له ولا يمكنه تجاوز صلاحيات المحرر. |
| **`manage_subagents`** | إدارة ومراقبة الوكلاء الفرعيين (List / Kill). | متابعة تقدم الوكلاء والتأكد من إتمام مهامهم واسترجاع نتائجهم. | لا يحتاج إلى عمل Polling مستمر لأن النظام يدعم الاستيقاظ التفاعلي (Reactive Wakeup). |
| **`send_message`** | التواصل وإرسال التوجيهات للوكلاء الفرعيين. | توجيه وكيل فرعي لتعديل مسار بحثه أو طلب مزيد من الأدلة حول ملف معين. | لا تُستخدم للتواصل مع المستخدم البشري؛ بل للوكلاء فقط. |
| **`manage_task`** | متابعة المهام غير المتزامنة وإرسال مدخلات لها. | فحص العمليات الخلفية التي تستغرق وقتاً طويلاً. | لا تُستخدم لتجاوز مهلات الأمان. |
| **`search_marketplace`** | استكشاف المهارات والإضافات في Agent Marketplace. | التحقق من وجود إضافات مفيدة للتوثيق والتحليل. | لا يتم تثبيت إضافات دون موافقة. |
| **`list_plugin_accounts`** | سرد الحسابات المتصلة بالإضافات. | التحقق من حسابات التكامل الخارجية. | لا تكشف الأسرار أو التوكنز الحساسة. |

## 2. استراتيجية تشغيل الوكلاء الفرعيين بالتوازي (Subagents Execution Plan)

بما أن البيئة تدعم `invoke_subagent` و `define_subagent`، سنقوم بتوزيع مهام التدقيق الكبيرة لضمان سرعة وعمق التغطية:
1. **وكيل تدقيق محرك المحادثة الحالي (`Agent-Engine-Forensics`):**
   - *الهدف:* فحص `packages/services/conversational_agent_engine.py` و `conversation_fsm_service.py` واستخراج كل نقاط الفشل وتتبع regex و prompt building.
2. **وكيل فحص المشاريع المرجعية (`Reference-Frameworks-Researcher`):**
   - *الهدف:* فحص تفصيلي لـ `memento-skills` و `ragleap-core` و `langgraph` من المجلد المحلي `D:\AI-Employee-Platform-Research`.
3. **الوكيل الرئيسي (نحن):**
   - *الهدف:* التنسيق، فحص قواعد البيانات والـ migrations، فحص الـ APIs، مراجعة مصفوفة المقارنة، كتابة المعمارية المستهدفة، وتحديث السجلات الحية فوراً.
